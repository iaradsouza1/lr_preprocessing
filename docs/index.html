lr_pipeline

long-read isoform discovery · QC · quantification
Snakemake workflow · reproduces Shimada et al. 2024

From long reads to a clean, quantified isoform catalog.

A generic, samplesheet-driven pipeline for PacBio HiFi and Oxford Nanopore cDNA. It discovers transcript isoforms with IsoQuant, cleans them of artifacts with SQANTI3, then re-quantifies against the filtered catalog — one path, two platforms, driven entirely by config.

reference GRCh38 + GENCODE v41 orchestrator Snakemake ≥8 envs lr_pipeline + sqanti3 profiles local · slurm input FASTQ (full-length reads)

Preprocess reads

workflow/rules/preprocess.smk · prepare_reads
per sample

Keep reads in the informative length window (100–15000 bp). ONT cDNA that isn't oriented is first run through pychopper to find and orient full-length reads. PacBio HiFi reads are already full-length and oriented, so they go straight to the length filter.

pychopper seqkit seq -m 100 -M 15000

↓ inputs

fastqraw reads

↑ outputs

fastqreads/{sample}.filtered.fastq.gz
pychopper -t $threads reads.fastq oriented.fastq   # ONT, oriented=no only
seqkit seq -m 100 -M 15000 reads.fastqoriented.fastq | gzip > {sample}.filtered.fastq.gz
03

Align — minimap2 (splice-aware)

workflow/rules/align.smk · minimap2_align
per sample

Spliced alignment to GRCh38 with the --MD tag (needed downstream), secondary alignments dropped, then filtered to MAPQ ≥ 10, sorted and indexed. These whole-genome BAMs are kept as durable outputs. The preset switches by platform.

minimap2 -ax splicesamtools view -q 10samtools sort/index

↓ inputs

fastq{sample}.filtered.fastq.gz
fagenome

↑ outputs

bamalign/{sample}.sorted.bam (+ .bai) · kept
minimap2 -ax splice:hq -uf -C5splice -uf --MD --secondary=no genome.fa reads.fastq.gz \
  | samtools view -q 10 -b - | samtools sort -o {sample}.sorted.bam -
samtools index {sample}.sorted.bam

05

IsoQuant — discovery & quantification

workflow/rules/isoquant.smk · isoquant_discovery
per platform

All BAMs of one platform go into a single IsoQuant run — it takes one --data_type, so PacBio and ONT are separate invocations. Reads are grouped back to samples with --read_group file_name, giving a novel-and-known transcript catalog plus counts.

isoquant.py

↓ inputs

bamall {platform} sorted BAMs
gtfgencode.v41 (guide)

↑ outputs

gtfisoquant/{platform}/models.gtf
tsvdiscovery_grouped_counts.tsv
isoquant.py --data_type pacbio_ccsnanopore --reference genome.fa --genedb gencode.v41.gtf \
  --bam {platform}/*.sorted.bam --read_group file_name --output isoquant/{platform}

SQANTI3 — QC & classification

workflow/rules/sqanti.smk · sqanti3_qc [env: sqanti3]
per platform

Classify every discovered model against GENCODE v41 (FSM / ISM / NIC / NNC / …) and compute the artifact descriptors — CAGE support, polyA motifs, RT-switching, intra-priming — that the next stage filters on. Runs in SQANTI3's own conda env.

Inputs what you provide

Two files. The pipeline is generic — point the samplesheet at any FASTQs and set the config once.

samplesheet config/samples.tsv
columnmeaning
sampleunique id
groupregion / condition
platformpacbio | ont
orientedyes | no (ONT → pychopper)
fastqabsolute path to reads
config config/config.yaml
  • referencegenome + GTF URLs (GRCh38, GENCODE v41)
  • conda_envmain env name — lr_pipeline
  • conda_env_sqantiSQANTI3 env name — sqanti3
  • length_filtermin 100 · max 15000
  • qcidentity thresholds + gate mode
  • platformsminimap2 preset + IsoQuant data_type
  • downstreamapp table / SUPPA2 / DESeq2 toggles
◆
Input is full-length reads FASTQ — HiFi for PacBio, basecalled cDNA for ONT. Raw PacBio subreads need ccs first (out of scope). A ready SG-NEx A549 test pair ships in config/samples_sgnex.tsv.

Running it two envs · pick a profile

Build the two conda environments once, then launch with the local or slurm profile. Rules reference their env by name, so nothing is rebuilt per run.

1 Build environments (once)
# main env (name: lr_pipeline)
conda env create -f workflow/envs/lr_pipeline.yaml
# clone SQANTI3, then create its own env (name: sqanti3)
snakemake --profile profiles/local clone_sqanti3
conda env create -f resources/SQANTI3/SQANTI3.conda_env.yml
2 Dry-run & launch
snakemake --profile profiles/local --config samplesheet=config/samples_sgnex.tsv -n   # dry run
snakemake --profile profiles/local --config samplesheet=config/samples_sgnex.tsv      # local
snakemake --profile profiles/slurm --config samplesheet=config/samples_sgnex.tsv      # cluster
◆
Two platforms, two IsoQuant runs. Because IsoQuant takes a single --data_type, a mixed PacBio + ONT cohort is quantified as separate invocations — you get comparable catalogs side by side under results/.
